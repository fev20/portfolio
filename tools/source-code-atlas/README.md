# 오픈소스 코드 지도 생성기 · Code Atlas

Python 프로젝트에서 함수 호출을 찾아 지도로 보여주는 한국어 정적 웹 앱입니다. 첫 화면의 **공개 예제 열기**로 바로 탐색하거나, **Python 폴더 선택**으로 자기 프로젝트를 읽을 수 있습니다. 방문자에게 계정이나 설치가 필요하지 않습니다.

## 실행 및 배포

개발에는 Node.js 20 이상과 npm이 필요합니다. 이 폴더에서 다음을 실행합니다.

```sh
npm ci
npm run build
npm run dev
```

로컬 데모: [http://127.0.0.1:4173/source-code-atlas/](http://127.0.0.1:4173/source-code-atlas/). `dist/`가 완성된 정적 빌드입니다. 모듈과 Web Worker가 동작하려면 HTTP(S)로 열어야 합니다.

- 포트폴리오의 **AI in Practice** 카드가 `/source-code-atlas/`로 연결합니다. 소스를 바꾼 후 이 폴더에서 `npm run build:portfolio`를 실행해 `client/public/source-code-atlas/`의 정적 파일을 갱신하세요.
- 포트폴리오 루트에서 `pnpm run build:pages`를 실행하면 `dist/public/source-code-atlas/`에 포함됩니다. GitHub Pages 워크플로는 이 정적 파일을 포트폴리오와 함께 배포합니다.

**카드 제목:** 오픈소스 코드 지도 생성기

**카드 소개:** Python 함수가 서로 어떻게 이어지는지 호출 지도로 탐색합니다. 공개 예제로 시작하거나, 내 프로젝트를 업로드 없이 분석하고 연결선마다 실제 코드와 줄 번호를 확인할 수 있습니다.

## 사용법

1. 공개 예제를 열거나 Python 프로젝트 폴더를 고릅니다. 예제에서는 위쪽의 경로 버튼으로 세 가지 기능까지 바로 이동할 수 있습니다.
2. 자동 진입점을 사용하거나 목록에서 다른 함수를 고릅니다. 검색 결과를 선택하면 현재 진입점에서 해당 함수까지 확인된 가장 짧은 경로를 표시합니다. 경로를 찾지 못해도 함수의 정의는 볼 수 있습니다.
3. 함수나 연결선을 선택합니다. 근거 패널에 정의, 호출 위치, 줄 번호와 실제 소스가 나옵니다. 점선과 `?`는 대상을 확정하지 못한 호출입니다. 공개 예제의 소스 링크는 고정 커밋의 해당 줄을 엽니다.

## 분석 범위와 개인정보

Lezer Python 문법으로 구문 트리를 만든 다음 선언과 호출 위치를 수집합니다. 같은 모듈, 모듈·심볼 import 별칭, 패키지 상대 import, 일부 정적으로 알려진 클래스 및 인스턴스의 메서드를 연결합니다. `__main__` 가드, `__main__.py`, `main`·`cli` 등의 후보를 보여주며 원하는 함수를 직접 선택할 수도 있습니다. 프로젝트 설정, Python 스크립트, 플러그인을 실행하지 않습니다.

콜백, `getattr`, 외부 라이브러리, 상속, 런타임 재할당, 반환 타입 등으로 대상이 달라질 수 있습니다. 분석기가 확정하지 못하면 미해결로 표시합니다. 지도는 실행 추적이 아니므로 조건, 실제 실행 순서, 런타임의 모든 호출을 재현하지 않습니다. 일반 프로젝트 루트와 `src/` 레이아웃을 지원합니다. 읽을 수 없는 구문은 위치를 알리고 가능한 부분을 표시합니다.

폴더 입력에서 `.py` 텍스트만 읽고 가상 환경·캐시·빌드 폴더 등은 건너뜁니다. 분석은 Web Worker에서 수행하고, 입력과 결과는 현재 탭의 메모리에만 둡니다. 앱은 외부 요청, 분석용 백엔드, 브라우저 저장소, 쿠키, 서비스 워커를 사용하지 않습니다. 배포된 앱을 열 때는 정적 자산만 받고, GitHub 링크는 공개 예제를 볼 때 사용자가 선택하는 링크입니다. 로컬 프로젝트의 코드 링크를 외부에 만들지 않습니다. 새로고침하면 로컬 분석이 사라집니다.

한 번에 Python 파일 최대 800개, 파일당 768 KiB, 전체 12 MiB까지 읽습니다. 큰 그래프는 진입점 주변의 일부를 보여주며 검색과 선택 함수 경로를 통해 나머지를 탐색할 수 있습니다.

## 예제와 검증

[asottile/add-trailing-comma v3.2.0](https://github.com/asottile/add-trailing-comma/commit/73c775a66303f25cbf03b0c2e3c14e71253f198a)의 Python 패키지 파일 15개와 [MIT 라이선스](./example/LICENSE.txt)를 포함합니다. 예제 파일은 빌드에 포함되어 실행할 때 GitHub에서 가져오지 않습니다. [세 경로의 호출·정의 줄과 검증 기록](./example/README.md)을 참조하세요. 빌드는 `dist/THIRD-PARTY-NOTICES.txt`에 파서와 의존성의 라이선스도 포함합니다.

```sh
npm test
npm run build
npm run test:browser
```

브라우저 검증은 설치된 Chrome·Edge·Chromium을 사용하고 임시 로컬 HTTP 서버를 엽니다. 자동으로 찾지 못할 때는 `ATLAS_CHROME`에 실행 파일 경로를 지정하세요. 테스트는 배포 파일의 예제 경로와 고정 링크, 실제 폴더 선택 입력, 검색, 호출 및 정의 근거, 모바일 레이아웃, 새로고침, 네트워크와 저장소를 확인합니다. 화면 캡처는 `.qa/`에 생성됩니다.

이 작업공간에서는 분석기 테스트 7개와 Chrome 156의 브라우저 검증이 통과했습니다. 데스크톱과 너비 390px에서 탐색을 확인했습니다. 전체 흐름의 요청 15건은 모두 본문 없는 동일 출처 정적 GET이었고, 로컬 분석과 탐색 구간에는 분석 Worker 파일을 받는 GET 한 건만 있었습니다. localStorage, sessionStorage, IndexedDB, Cache Storage, 쿠키는 비어 있었고 새로고침 후 폴더 입력과 지도 상태가 초기화됐습니다.
